## 1. 全体構成

```
[スマホ / PC のブラウザ]
   │  index.html（css.html と js.html を include で埋め込む）
   │  google.script.run（非同期）
   ▼
[GAS ウェブアプリ（Code.gs）]  … 実行ユーザー: 自分 / アクセス: 全員
   │  SpreadsheetApp・CacheService・LockService・DriveApp・Utilities
   ▼
[スプレッドシート（このスクリプトの紐づけ先）]
   ├─ 圧力設定変更履歴 / 基準パターンマスタ / 入力者マスタ / 品種マスタ / 設定 / 操作ログ
[Google ドライブ]
   ├─ 移行用フォルダ（MIGRATION_FOLDER_ID）
   └─ バックアップ用フォルダ（BACKUP_FOLDER_ID）
```

- 外部の API やライブラリは使わない。
- clasp は使わず、GAS エディタに貼り替えて反映する（D-08）。

## 3. 画面構成

タブで切り替える1ページのアプリ（D-12）。タブはスマホ・タブレットでは画面の下、PC ではヘッダの中に並ぶ（K-30）。

| 画面 | ID | 開き方 | 内容 |
|---|---|---|---|
| ホーム | S-01 | タブ | 今の設定、直近5件、「設定を変更して記録する」 |
| 入力 | S-02 | タブ | 記録の入力と登録 |
| 履歴 | S-03 | タブ | 一覧、絞り込み、ページ送り |
| 記録の詳細と修正 | S-04 | 一覧のカードを押す（下から出るモーダル） | 表示、修正、削除、元に戻す |
| パターン表 | S-05 | タブ | 基準パターンの早見表 |
| 管理者モード | S-06 | ヘッダの鍵 | 管理者認証（パスワード）、削除済みの表示、操作ログ |
| 操作者を選ぶ | — | 初回、ヘッダの操作者 | 入力者マスタの有効な人から選ぶ |

- ヘッダ: ロゴ（圧力計）、アプリ名、開発環境なら「開発」バッジ（K-27）、操作者、管理者モード。デザインはロッカーキー貸出管理・エネルギー使用量集計にそろえる（plan/05 §0、plan/11）。
- 幅375pxを基準にし、タップできる部品は44px以上。
- 表示: パターンは「パターンN」、設定者は「記入称(氏名)」（入力者マスタの氏名。マスタに無い・氏名が空なら記入称だけ。ヘッダの名前のボタンも同じ）。
- ヘッダ（スマホ）: 名前のボタンは縮めずに全部見せ、アプリ名の方を縮める（…で省略）。管理者モードのボタンは、スマホでは「n分」だけ、タブレット・PC では「管理者 n分」。

### 3.1 画面の幅ごとの表示（K-30）

| 区分 | 幅 | 表示 |
|---|---|---|
| スマホ | 〜767px | 1列。タブは画面の下。ページ送りは「‹ 前へ」「n / N ページ（選ぶ）」「次へ ›」 |
| タブレット | 768〜1023px | 最大幅 960px。ホームは左右2列、履歴のカードとパターン表は2列。ページ送りは番号のボタン。タブは画面の下 |
| PC | 1024px〜 | 最大幅 1200px。ヘッダは灰色の帯の中の白いカード（高さ 88px）。タブはヘッダの右にセグメントの形。履歴は表の形（変更日時・パターンと燃料・圧力・設定者・品種・備考）で、絞り込みは常に開く。入力は左右2列。詳細などのダイアログは画面の中央 |

- 日付・時刻の欄は、ブラウザ独自の見た目をやめ（`appearance: none`）、高さ48pxに固定し、2列の枠からはみ出さないようにする（`minmax(0, …)`。日付 1.3 : 時刻 1）。実機で隣の欄と重なる・文字が上に寄るのを防ぐため。
- ヘッダ（画面上部）はどの幅でもスクロールしても上に残す（`position: sticky`）。PC の履歴の表の項目名は、ヘッダのすぐ下に残す。`body` と履歴の表は `overflow: clip` にする（`hidden` だと GAS の枠の中で sticky が効かなくなるため）。
- css.html の `@media (min-width: 768px)` と `@media (min-width: 1024px)` で切り替える。HTML は同じものを使い、PC の履歴の表は記録のカードを CSS の grid で並べ直す。

## 4. 処理の流れ

### 4.1 起動
1. `doGet` が index.html を返す。
2. 画面が `getInitialData(ctx)` を呼び、設定・マスタ・今の設定・直近の記録をまとめて受け取る。
3. 操作者が未選択か無効なら、操作者を選ぶモーダルを出す。

### 4.2 登録
1. 入力 → 画面側のチェック → 確認ダイアログ。
2. `createRecord(ctx, payload)` → ロック → 入力チェック → 採番 → マスタとの差異を計算 → 1行追加 → 操作ログ。
3. ホームへ戻って読み直す。

### 4.3 修正・削除
1. 詳細を開く（`getRecord` が権限 can〜 を返す）。
2. `updateRecord` / `deleteRecord` / `restoreRecord` → ロック → 版数の照合 → 権限の確認 → 反映 → 操作ログ。
3. 管理者の権限が要る操作でトークンがなければ、管理者認証のダイアログを出し、認証できたらやり直す。

詳細は docs/04 第1部 §6、第2部 §2〜§5。

## 5. 通信と認証

- 画面の `api(関数名, ...引数)` が `google.script.run` を Promise に包む。戻り値は `{ok, data, error}`（docs/04 第2部 §1.2）。
- 画面から呼ぶ関数は、第1引数に `ctx = { operatorId, token }` を受け取る。
- `Session.getActiveUser()` は使わない（匿名アクセスのため）。
- 管理者のトークンは ScriptCache に30分保存する。画面側は sessionStorage（`boilerPressure.adminToken`）に持つ。
- 選んだ操作者は localStorage（`boilerPressure.operatorId`）に持つ。
- 履歴の絞り込みの条件は sessionStorage（`boilerPressure.historyFilter`）に持つ（タブを切り替えても残す）。
