## 0. まず画面を見る（ローカル）

GAS に貼らなくても、PC のブラウザで画面と動きを確かめられる。

1. `node tools/build_local_preview.js` を実行する。
2. `local_preview.html` をブラウザで開く。スマホの幅で見るときは `tools/mobile_frame.html` を開く。
3. 上のバナーで、操作者の切り替え、管理者モード（管理者パスワード `boiler`）、データの初期化ができる。
4. データは架空のもので、このブラウザの localStorage だけに保存される。

## 1. 開発環境

### 1.1 スプレッドシートを作る
1. Google ドライブで、新しいスプレッドシート `ボイラ圧力設定DB_開発` を作る。
2. 移行用とバックアップ用のフォルダを作る（例: `ボイラ圧力設定_移行`、`ボイラ圧力設定_バックアップ`）。フォルダの ID（URL の `folders/` の後ろ）を控える。

### 1.2 GAS プロジェクトを作る
1. スプレッドシートの「拡張機能 → Apps Script」を開く。
2. プロジェクト名を `ボイラ圧力設定管理_開発` にする。
3. §2 の手順で、`gas_app/` のファイル（Tests.gs を含む）を貼る。

### 1.3 初期設定【フェーズ1 以降】
1. スプレッドシートを開き直し、メニュー「ボイラ圧力設定 → 初期設定（シートの作成）」を実行する。最初の1回は権限の承認を求められるので、承認する。
2. 「設定」シートの `MIGRATION_FOLDER_ID` と `BACKUP_FOLDER_ID` に、§1.1 のフォルダ ID を入れる。`ENV` が `開発` になっていることを確かめる。
3. GAS エディタの「プロジェクトの設定（歯車）→ スクリプト プロパティ → スクリプト プロパティを追加」で、プロパティ `ADMIN_PASSWORD`、値に管理者パスワード（2文字以上）を入れて保存する。

### 1.4 既存データの移行【フェーズ2 以降】
1. PC で `node tools/migrate/convert_excel.js "reference/ボイラ圧力設定変更履歴.xlsx" "reference/移行データ"` を実行する。
2. `reference/移行データ/report.md` を開き、件数・内訳・品種の振り分け・当てはまらなかった備考を確かめる。
3. `records.csv`、`patterns.csv`、`operators.csv`、`products.csv` の4つを、移行用フォルダにアップロードする。
4. メニュー「移行データ取込」を実行する。結果のダイアログで、件数と内訳が期待どおりか確かめる（docs/04 第1部 §13.5）。
5. やり直すときは、開発用のスプレッドシートを作り直す（取込は、移行データが1件もないときだけ実行できる。K-17）。
6. 「開発: サンプルデータ投入」を実行したスプレッドシートには取り込めない（サンプルにも「移行」の記録が入るため）。実データを入れる開発用スプレッドシートでは、サンプルデータを入れないこと。

### 1.5 テスト【フェーズ1 以降】
- メニュー「開発: テストを実行」で、Tests.gs のテストを GAS 上で動かす。結果はダイアログと実行ログに出る。
- フェイクでしか作れない状態（ロックが取れない、ダイアログへの入力、ドライブのファイル、トリガー、条件付き書式の中身）を使うテストは、GAS 上では SKIP になる（TC-LK-02、TC-AU-07、TC-MG-11、TC-BK-01〜03、TC-ST-02）。これらはローカルの `node tools/run_tests_node.js` で確かめる。
- テストは本物のシートに一時的な記録（2031年の日付）を足し、終わったら消す。実行中にアプリを使うと、その記録が一瞬見えることがある。

### 1.6 テスト デプロイで画面を確かめる【フェーズ3 以降】
1. GAS エディタの「デプロイ → デプロイをテスト」で、ウェブアプリの URL（末尾 `/dev`）を開く。
2. スマホで確かめるときは、「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」で作る。
   - 次のユーザーとして実行: 自分
   - アクセスできるユーザー: 全員
3. 出てきた URL をスマホで開く。

### 1.7 フェーズ8（本番前の修正）を開発環境に入れる（T8-6）
品種マスタが8つに変わったため、開発環境の記録の品種名（例:「2L麦茶」）は新しいマスタに無く、その記録は修正できなくなる。開発環境は作り直して取り込み直す（plan/10 C-2）。開発環境でアプリから登録したテストの記録は消える。

1. 今の開発用スプレッドシート `ボイラ圧力設定DB_開発` の名前を `ボイラ圧力設定DB_開発_旧` に変える（念のため残す。不要になったらゴミ箱へ）
2. §1.1〜§1.3 の手順で、新しい `ボイラ圧力設定DB_開発` と GAS プロジェクトを作り、`gas_app/` の6ファイル（Tests.gs を含む）を貼る
3. メニュー「初期設定（シートの作成）」。スクリプト プロパティ `ADMIN_PASSWORD` を入れる（§1.3）。「設定」シートの `MIGRATION_FOLDER_ID`・`BACKUP_FOLDER_ID` を入れる（`HISTORY_PAGE_SIZE` は 20 で自動的に入る）
4. 変換し直した4つの CSV（`reference/移行データ/`。2026/11/15 に変換済み）を移行用フォルダに置き直し、メニュー「移行データ取込」。品種の内訳が report.md と同じか確かめる
5. 基準パターンマスタの「主要品種」を手で直す
6. メニュー「開発: テストを実行」で NG 0 件を確かめる
7. テスト デプロイの URL を、スマホ・タブレット・PC のブラウザで開いて確かめる（履歴のページ送り、「パターンN」「記入称(氏名)」の表示、PC の表の形）

### 1.8 フェーズ9（デザインの統一・管理者パスワード）を入れる（plan/11）
管理者パスワードの置き場所が、設定シートからスクリプトプロパティに変わる。**先にスクリプト プロパティを入れてから、Code.gs を貼る**（逆にすると、入れるまで管理者モードに入れない）。

開発環境:
1. GAS エディタの「プロジェクトの設定 → スクリプト プロパティ」で `ADMIN_PASSWORD` を入れる（§1.3 の3）
2. Code.gs・Tests.gs・index.html・css.html・js.html を貼り替える（§2）
3. 「設定」シートの `ADMIN_PIN_SALT`・`ADMIN_PIN_HASH` の行を、行ごと削除する
4. メニュー「開発: テストを実行」で NG 0 件を確かめる（スプレッドシートを開き直すと、メニューから前の版の「管理者暗証番号を設定」が消えている）
5. テスト デプロイの URL をスマホ・PC で開き、鍵のボタン →「管理者認証」で入れること、見た目を確かめる

本番（ユーザーの指示があってから）:
1. 本番の GAS プロジェクトのスクリプト プロパティに `ADMIN_PASSWORD` を入れる（開発用とは別にする）
2. Code.gs・index.html・css.html・js.html を貼り替え、「デプロイを管理 → 編集 → 新バージョン」（URL は変わらない。Tests.gs は貼らない）
3. 「設定」シートの `ADMIN_PIN_SALT`・`ADMIN_PIN_HASH` の行を削除する
4. 管理者に、新しいパスワードと「入る」ボタンが「認証する」に変わったことを伝える

### 2.1 手順
1. 実装 AI の完了報告にある「貼り替えが必要なファイル」だけを貼り替える。
2. 原本の中身を丸ごとコピーし、GAS エディタのファイルの中身をすべて選んで置き換え、保存する。
3. ウェブアプリに反映するときは、「デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン → デプロイ」を選ぶ（URL は変わらない）。
4. デプロイ ID とスクリプト ID は、文書や history に書かない。

## 3. 本番環境【ユーザーの指示があってから】

上から順に行い、終わったら □ に印を付ける。

### 3.1 準備
- □ 開発環境で、メニュー「開発: テストを実行」が NG 0 件であることを確かめる
- □ 開発環境のテスト デプロイで、スマホから登録・履歴・修正・管理者の削除を一通り試す（plan/07 の T2-7・T3-6・T4-4・T6-5）
- □ 本番を始める日を決め、その日までは Excel にも記録を続けてもらう

### 3.2 スプレッドシートと GAS
- □ Google ドライブに、本番用のスプレッドシート `ボイラ圧力設定DB` を作る
- □ 本番用の移行用フォルダとバックアップ用フォルダを作り、ID を控える（開発用とは別にする）
- □ 「拡張機能 → Apps Script」でプロジェクトを作り、名前を `ボイラ圧力設定管理` にする
- □ `gas_app/` の Code.gs、index.html、css.html、js.html、appsscript.json を貼る（**Tests.gs は貼らない**。§2）
- □ スプレッドシートを開き直し、メニュー「初期設定（シートの作成）」を実行して権限を承認する
- □ 「設定」シートの `ENV` を `本番` に、`MIGRATION_FOLDER_ID` と `BACKUP_FOLDER_ID` を本番用のフォルダの ID にする
- □ スクリプト プロパティ `ADMIN_PASSWORD` に、本番の管理者パスワードを入れる（開発用とは別にする。§1.3 の3）

### 3.3 データの移行（本番を始める直前）
- □ 最新の Excel を `reference/ボイラ圧力設定変更履歴.xlsx` に置き直す
- □ `node tools/migrate/convert_excel.js "reference/ボイラ圧力設定変更履歴.xlsx" "reference/移行データ"` を実行する
- □ `report.md` で件数・内訳・当てはまらなかった備考を確かめる（件数は Excel の行数と同じか。154件より増えているのは正常）
- □ 4つの CSV を本番の移行用フォルダにアップロードし、メニュー「移行データ取込」を実行する
- □ ダイアログの件数・パターン別・燃料別・マスタとの差異が report.md と同じであることを確かめる
- □ 基準パターンマスタの「主要品種」を、新しい品種名（品種マスタの8つ）に合わせて手で直す（**取込のあとに行う**。取込はパターンマスタを CSV の内容で置き換えるため）
- □ 移行用フォルダの CSV は、取込のあと削除する（個人名を含むため。ゴミ箱へ移す）

### 3.4 公開
- □ メニュー「バックアップのトリガーを設定」を実行し、続けて「今すぐバックアップ」でバックアップ用フォルダに複製ができることを確かめる
- □ 「デプロイ → 新しいデプロイ → ウェブアプリ」（実行ユーザー: 自分、アクセス: 全員）を作り、URL を控える
- □ 自分のスマホで URL を開き、設定者を選んで1件登録し、ホームと履歴に出ることを確かめる（確かめた記録は、管理者モードで削除してよい）
- □ 利用者に URL と `docs/06_操作マニュアル.md`（ホーム画面への追加の手順を含む）を配る
- □ 元の Excel を読み取り専用にして保管する（D-27）。以後は Excel に記録しないよう案内する

## 4. 運用

| 作業 | 誰が | 方法 |
|---|---|---|
| 基準パターンの改定 | 管理者 | 基準パターンマスタのメイン圧力・サブ圧力・注記・改定日を直す。パターンの**番号は書き換えない**。新しいパターンは行を足す |
| 設定者の追加 | 管理者 | 入力者マスタに行を足す。入力者ID は続きの番号（U09〜）にし、一度振ったら変えない |
| 設定者の退職 | 管理者 | 入力者マスタの「有効」を FALSE にし、備考に「退職」と書く（行は消さない） |
| 品種の追加・廃止 | 管理者 | 品種マスタに行を足す／「有効」を FALSE にする（品種名は書き換えない） |
| 記録の直接編集 | — | 原則しない（シートは警告付きで保護している）。直すときはアプリの管理者モードで行う |
| バックアップ | 自動 | 毎月1日3時台。12か月より古いものはゴミ箱へ移る。手動はメニュー「今すぐバックアップ」 |
| 管理者パスワードの変更 | GAS プロジェクトの持ち主 | GAS エディタの「プロジェクトの設定 → スクリプト プロパティ」で `ADMIN_PASSWORD` の値を書き換える（すぐに効く。管理者モード中の人は、時間が切れるまでそのまま） |

## 6. ローカルでの検証

| コマンド | 内容 |
|---|---|
| `node tools/run_tests_node.js` | フェイクの上で、pure テストと結合テストを動かす。NG があれば終了コード1 |
| `node tools/run_tests_node.js --pure` | GAS のサービスを使わないテストだけ |
| `node tools/run_tests_node.js --verbose` | フェイクのログ（ダイアログの内容など）も出す |
| `node tools/build_local_preview.js` | local_preview.html を作り直す（画面を変えたら必ず実行） |
| `node tools/screenshot.js "tab=home&op=U01" screenshot/xxx.png [幅] [--full]` | local_preview を撮影する（Chrome を使う。追加パッケージなし） |
| `node tools/ui_checks.js [出力フォルダ]` | 画面の確認（plan/08 の TC-UI など）を幅375pxでまとめて行い、確認用の画像を撮る（数分かかる） |
| `node tools/capture_manual.js` | 操作マニュアルの画像を `docs/images/` に撮り直す（画面を変えたら実行） |

- 必要なもの: Node.js 22 以降、Google Chrome（場所が違うときは環境変数 `CHROME_PATH`）。
- フェイクは Code.gs が使う範囲だけを再現している。ドライブ・ロック・トリガー・シートの書式の本当の動きは、開発環境で確かめる。
