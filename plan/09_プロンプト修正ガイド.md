## 2. フェーズ別の実装用プロンプト

### 2.1 共通の書き出し
```
plan/README.md を読み、書かれている順に計画書を確認してください。
docs/ がある場合は docs を正とし、plan と食い違いがあれば報告してください。
コードを変更する前に、変更する内容と理由を説明して確認を取ってください。
```

## 4. 確認事項（Q-xx）が決まったときの反映手順

1. 01 の該当する K-xx の「状態」を「確定」にする（内容が変わるなら書き換える）。§4 の Q-xx の行に、決まった内容と日付を書く。
2. §3 の表で、続けて直す計画書とコードを確かめる。
3. docs ができていれば、docs も直す。
4. 01 §5 の改版履歴に1行足す。

プロンプトの例:
```
plan/01 の Q-01 は「時刻の値で持つ」に決まりました。
plan/09 §3 の表に従って、直す計画書・docs・コードを一覧にし、変更の案を示してください（まだ直さないでください）。
```
