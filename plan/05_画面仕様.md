## 1. 共通

### 1.1 画面の骨組み
```
┌─────────────────────────────┐
│ ボイラ圧力設定管理 [開発]   [👤 h ▼] [🔑] │ ← ヘッダ（固定）
├─────────────────────────────┤
│                             │
│        （各タブの中身）        │
│                             │
├─────────────────────────────┤
│  🏠ホーム  ✏入力  🕘履歴  ▦パターン表  │ ← タブバー（固定）
└─────────────────────────────┘
```
- ヘッダ: アプリ名、ENV が `開発` なら「開発」バッジ（K-27）、操作者のボタン（記入称。押すと操作者を選ぶモーダル）、鍵のボタン（管理者モードの出入り）。
- 管理者モードの間は、鍵のボタンを `--warning` の色の「管理者」バッジに変え、残り時間（分）を出す。押すとログアウトの確認を出す。
- タブを切り替えても、ページは読み込み直さない。URL のハッシュ（`#home` など）に今のタブを入れる。

### 1.2 起動の流れ
1. ローディングを出し、`getInitialData(ctx)` を呼ぶ。
2. localStorage に入力者ID がない、または有効な人でなければ、操作者を選ぶモーダル（§2）を閉じられない形で出す。
3. ホームを表示する。

### 1.3 エラーの扱い
| エラーコード | 画面の動き |
|---|---|
| VALIDATION | 欄ごとのエラーを表示し、最初のエラーの欄までスクロールする |
| AUTH_REQUIRED（操作者が無効） | 操作者を選ぶモーダルを出す |
| AUTH_REQUIRED（管理者が必要） | 管理者認証のダイアログを出し、認証できたら同じ操作をやり直す |
| AUTH_FAILED / AUTH_LOCKED | ダイアログの中に文言を出す |
| FORBIDDEN / NOT_FOUND / CONFLICT / BUSY / SYSTEM | エラーのダイアログを出す（文言は §8）。CONFLICT と NOT_FOUND は、閉じたら一覧を読み直す |

ブラウザ標準の alert / confirm / prompt は使わない。

## 2. 操作者を選ぶモーダル
- 有効な入力者を表示順に、大きなボタンで並べる。表示は「記入称（氏名）」（D-23）。

## 3. ホーム（S-01）
```
┌ 今の設定 ─────────────────────┐
│ パターン 2              [ガス]  │
│ 0.67 MPa                       │
│ 2026/11/12 10:40  設定者 h      │
│ 品種 2L(水)                     │
└───────────────────────────────┘
[ 設定を変更して記録する ]（メインのボタン、幅いっぱい）

直近の記録
┌ 11/12 10:40  [P2] [ガス]  0.67 ┐
│ h ・ 2L(水)                     │
└────────────────────────────────┘
 …（5件）
[ 履歴をすべて見る ]
```
- 今の設定のカード: パターン番号と圧力を大きく（圧力は40px程度）。マスタとの差異があれば「基準と違う」バッジ。
- 記録がないときは「まだ記録がありません」と表示する。
- 直近の記録のカードを押すと、詳細（§6）を開く。
- 「設定を変更して記録する」は入力タブへ移る。

## 4. 入力（S-02）

上から次の順に並べる。

| 順 | 項目 | 部品 | 動き |
|---|---|---|---|
| 1 | 設定パターン | 選択ボタンの列。各ボタンに番号とメイン圧力（例: 「2」「0.67」） | 押すと圧力の欄にメイン圧力を入れる（04 §5） |
| 2 | メインボイラ | 選択ボタン「ガス」「重油」 | |
| 3 | 設定圧力(MPa) | [−] 数値の欄 [＋]。`inputmode="decimal"`、0.01刻み | 欄の下に「基準: 0.67」。違えば注意の枠（M-21） |
| 4 | 日付・時刻 | `input type="date"` と `input type="time"` を横に並べる | 入力タブを開くたびに今の時刻にする（K-29）。「今にする」ボタン |
| 5 | 設定者 | 今の操作者を表示（変えるときはヘッダの操作者ボタン） | 変えられないことを小さく案内する |
| 6 | 生産品種 | セレクト（有効な品種＋空） | |
| 7 | 備考 | テキストエリア（3行）、右下に「12/200」 | |
| 8 | 登録する | メインのボタン（幅いっぱい、画面の下に固定） | |

- 初期値: パターンと燃料は今の設定から（K-29）。今の設定がなければ未選択。
- 「登録する」を押したら、画面側でもチェックし、確認のダイアログを出す。
  - 中身: 日時、パターン、燃料、圧力、設定者、品種、備考。
  - マスタと違うときは「基準（0.67）と違う値です」、未来の日時のときは「未来の日時です」を、注意の枠で出す。
  - ボタン: 「戻る」「登録する」。
- 登録できたら、トースト（M-01）を出してホームへ移り、ホームを読み直す。フォームは初期値に戻す。

## 5. 履歴（S-03）
```
[絞り込み ▼]  全154件中 50件を表示   [条件をクリア]
（管理者のとき）[□ 削除済みも表示]  [操作ログ]

┌ 2026/11/12 10:40   [P2] [ガス] ┐
│ 0.67 MPa  ⚠                     │
│ h ・ 2L(水) ・ 2L(水)…（1行で省略）│
└────────────────────────────────┘
 …
[ もっと見る ]
```
- 絞り込みの欄（開閉できる）: 期間（から・まで）、パターン、メインボイラ、設定者（無効な人は名前の後ろに「（無効）」）、生産品種（`（未設定）` を含む）。「この条件で表示」で検索する。
- 条件は sessionStorage に残し、タブを切り替えても消えないようにする。
- 「もっと見る」で、次の50件を後ろに足す（K-11）。最後まで読んだら、ボタンを消す。
- カードを押すと詳細（§6）を開く。
- 削除済みのカードは、文字を薄くして「削除済み」のバッジを付ける。
- 0件のときは「条件に合う記録はありません」と表示する。

## 6. 記録の詳細と修正（S-04）
下から出るモーダル（K-24）。

- 表示: 日付・時刻、パターン、メインボイラ、設定圧力（差異があればバッジ）、設定者、生産品種、備考、データ区分、記録ID、登録日時・登録者、更新日時・更新者。
- ボタン（`getRecord` の結果で出し分ける）:
  - 「修正する」（canEdit）: 同じモーダルの中を、入力と同じ部品のフォームに切り替える。設定者の欄は canChangeSetter のときだけセレクトにする。「キャンセル」「保存する」。
  - 「削除する」（canDelete）: 赤いボタン。確認ダイアログ（M-31）。
  - 「元に戻す」（canRestore）: 削除済みのときだけ。
- 修正も削除もできないときは、案内（M-24）を出す。
- 保存・削除・元に戻すが終わったら、トーストを出してモーダルを閉じ、開いているタブ（ホーム／履歴）を読み直す。

## 7. パターン表（S-05）と管理者モード（S-06）

### 7.1 パターン表
- 有効なパターンを表示順にカードで並べる: パターン番号、メイン圧力（大きく）、サブ圧力、主要品種、注記、改定日。
- 今の設定のパターンのカードは、枠を `--primary` にして「今の設定」バッジを付ける。

### 7.2 管理者モード
- 鍵のボタン → 管理者認証のダイアログ（`data-kind="pin"`）: 錠前の丸いアイコン、見出し「管理者認証」、説明「管理者パスワードを入力してください。認証すると{n}分間、すべての記録の修正・削除ができます」（{n} は AUTH_TOKEN_MINUTES）、入力欄（`type="password"`、薄い字「管理者パスワードを入力」）、「キャンセル」「認証する」。2文字未満は送らずに「パスワードは2文字以上です」。
- 入れたら、トークンを sessionStorage に保存し、ヘッダを管理者の表示に変える。残り時間は1分ごとに更新し、0になったら管理者モードを解く（M-14）。
- 管理者のときだけ、履歴タブに「削除済みも表示」と「操作ログ」を出す。
- 操作ログのモーダル: 新しい順に50件ずつ。日時、操作者、役割、操作、記録ID。記録ID を押すと詳細を開く。

## 9. local_preview.html

- `node tools/build_local_preview.js` で作る（K-25）。作り方は `02.物品購入届CSV出力/tools/build_local_preview.js` と同じ:
  - index.html の `<?!= include('css'); ?>` を css.html の中身に置き換える。
  - `<?!= include('js'); ?>` を「gas_fakes.js → Code.gs と Tests.gs を包んだ即時関数（`window.__GAS__` を作る）→ preview_mock.js → js.html」に置き換える。
  - `<body>` の直後に「LOCAL MOCK PREVIEW」のバナー（操作者の切り替え、管理者モードの ON/OFF、データの初期化）を入れる。
  - 置き換えていない `<?` が残っていたら、エラーで止める。
- preview_mock.js:
  - `google.script.run` を代わりのものに置き換え、`window.__GAS__` の関数を120ms 遅らせて呼ぶ。
  - 起動時に `menuSetup()` と `seedDevData()`（Tests.gs。架空の入力者と記録を30件ほど作る）を動かす。状態は localStorage（キー `boilerMock_v1`）に保存する。
  - URL のハッシュで状態を指定できる: `tab=home|input|history|patterns`、`op=U01`、`admin=1`、`open=記録ID`。
- `tools/mobile_frame.html`: 幅375px・高さ2000px の iframe で `../local_preview.html#tab=home&op=U01` を表示する。

## 10. 操作マニュアル

- `docs/06_操作マニュアル.md` に書く（K-26）。画像は local_preview を幅375pxで撮ったものを `docs/images/` に置く。
- 章立て: 1 はじめに（URL を開く、ホーム画面に追加する、名前を選ぶ） / 2 設定を変えたときの記録 / 3 今の設定と履歴を見る / 4 記録を直す / 5 管理者の操作（削除、元に戻す、操作ログ） / 6 スプレッドシートで見る / 7 困ったとき（よくあるエラー）。
