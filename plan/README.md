# ボイラ圧力設定管理アプリ 実装計画書

- 版: v1.0（2026/11/14。初版）
- 元資料: `plan_draft/00_実装計画書(要件定義).md`、`plan_draft/00_実装計画書(構築手順).md`、`reference/ボイラ圧力設定変更履歴.xlsx`
- 役割: 実装 AI（Claude Code / Gemini）が読み、コードを書いて実行するための計画書の入口

---

## アプリの概要

ボイラの圧力設定を変えたときに、スマホから記録する GAS のウェブアプリ。

- 入力: 設定パターンを選ぶと設定圧力が自動で入る（手で直せる）。メインボイラ（ガス／重油）、設定者、生産品種、備考を記録する。
- 閲覧: ホームに「今の設定」を大きく表示する。履歴は一覧で見られ、絞り込みもできる。基準パターン表も見られる。スプレッドシートでも閲覧できる。
- 修正: 本人はアプリで登録した自分の記録を直せる（期限なし）。管理者はすべての記録を直せる。削除は管理者だけ。
- 移行: Excel の履歴154件（2025/01/21〜2026/11/12）とマスタを、スプレッドシートへ移す。
- 構成: GAS の HtmlService で作る1ページのアプリ＋スプレッドシート。clasp は使わず、GAS エディタに貼り替えて反映する。

## 2. 実装AIへの作業ルール

### 2.1 プロジェクトのルール（CLAUDE.md / GEMINI.md）
フェーズ0で、プロジェクト直下に `CLAUDE.md`（と同じ内容の `GEMINI.md`）を作る。上位の CLAUDE.md のルールのうち、特に次を守る。

- やり取り、コメント、ドキュメントは日本語で書く。
- コードを変更する前に、変更する内容と理由を説明し、確認を得る。
- 調べるときはファイル全体を読まず、grep で該当箇所に絞る。
- ファイルやフォルダを消すときは、ゴミ箱へ移す。
- 修正は必要最小限の差分にする。
- `.env`、`secrets/`、`.clasprc.json`、`.clasp.json` は読まない。
- 修正したら、ファイルの一覧を示し、`history/YYYYMMDDhhmm_変更内容.md` を作る。
- スクリーンショットはいったん `screenshot/` 直下に置き、完了報告の前に `screenshot/YYYYMMDDhhmm_変更内容/` へ移す。
- 画面を変えたら `node tools/build_local_preview.js` を実行し、`local_preview.html` を作り直す。
- 関数名と変数名は camelCase、クラス名は PascalCase にする。コードは `gas_app/` に置く。

### 2.2 この計画に固有のルール
1. フェーズ0で `docs/01〜05` を作ったあとは、**docs を正とする**。plan と docs が食い違ったら、ユーザーに報告する。
2. D-xx（確定事項）は勝手に変えない。K-xx（仮決め）を変えたいときは理由を添えて提案し、承認を得てから 09 §3 のとおりに直す。
3. フェーズは順番に進める。各フェーズの終わりに、完了条件とテスト結果を報告し、確認を得てから次へ進む。
4. 終わったタスクは 07 で `[x]` にする。history には、フェーズ名、タスク、テスト結果の表（テストID と OK/NG）を書く。
5. 権限の判定と入力チェックは、**必ずサーバー側でも行う**（画面側のチェックは補助）。
6. 環境で変わる値（フォルダ ID、圧力の範囲など）は、「設定」シートに置く。コードに直接書かない。
7. 本番環境への反映とデプロイは、ユーザーから明示的な指示があるまで行わない。
8. ユーザーの手作業（GAS エディタへの貼り付け、権限の承認、デプロイ、メニューの実行）は、手順を示して依頼する。AI が代わりにやったとは報告しない。
9. 貼り替えで反映する前提にする。サーバー側は `Code.gs` の1ファイル、画面側は `index.html`、`css.html`、`js.html` の3ファイルにする（開発環境だけ `Tests.gs` を足す）。ファイルは増やさない。**完了報告では「GAS エディタへの貼り替えが必要なファイル」を列挙する。**
10. デザインは 05 §0 に従う。新しい部品が要るときは、先に参考アプリの `css.html` で近いものを探す。
11. 移行データ（`reference/移行データ/`）には個人名が入っている。計画書、docs、history、テストのコードに個人名を書き写さない。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 記録 | 圧力設定を1回変えたことを表す1行（履歴シートの1行） |
| 設定パターン | 基準パターンマスタの番号（1〜5）。メイン圧力とサブ圧力の組み合わせ |
| メインボイラ | 主に運転するボイラの燃料の種類（「ガス」か「重油」）。号機のことではない |
| 設定圧力 | メインボイラの設定圧力（MPa、小数2桁） |
| マスタとの差異 | 設定圧力が、そのパターンのメイン圧力と違うこと |
| 今の設定 | 削除されていない記録のうち、変更日時がいちばん新しいもの |
| 設定者 | 圧力を変えた人。入力者マスタから選ぶ（自己申告） |
| 記入称 | 設定者を表す1文字の略称（例: h、y、Y）。Excel から引き継ぐ（英数字は半角） |
| 入力者ID | 入力者マスタで1人ずつに振る ID（U01 など）。本人かどうかの判定に使う |
| 管理者モード | 管理者暗証番号を入れたあと30分間、すべての記録を修正・削除できる状態 |
| データ区分 | `移行`（Excel から移した記録）か `アプリ`（アプリで登録した記録）か |
| 移行データ | Excel から変換した CSV と、それを取り込んだ記録 |
| 開発環境 / 本番環境 | `ボイラ圧力設定DB_開発` / `ボイラ圧力設定DB` と、それぞれに紐づく GAS プロジェクト |
| 貼り替え | `gas_app/` の原本の中身を、GAS エディタのファイルへ丸ごと貼り付けること |
