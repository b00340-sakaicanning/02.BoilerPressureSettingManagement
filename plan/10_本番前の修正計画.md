## 1. PC・タブレットでの表示

今は、どの端末でも幅640pxの1列で表示し、タブは画面の下にある。画面の幅で3段階に分ける（CSS の `@media`）。

| 区分 | 幅 | 変えること |
|---|---|---|
| スマホ | 〜767px | 今のまま（変えない） |
| タブレット | 768〜1023px | 表示の最大幅を 960px にする。ホームは「現在の設定」と「最近の記録」を左右2列。履歴のカードを2列。入力は1列のまま、ボタンを横に並べる。タブは下のまま |
| PC | 1024px〜 | 表示の最大幅を 1200px にする。タブを画面上部のヘッダの中に移す。履歴は表の形（変更日時・パターン・燃料・圧力・設定者・品種・備考の列。行を押すと詳細）。絞り込みは表の上に常に開いておく。入力は左右2列（左: パターン・燃料・圧力／右: 日時・設定者・品種・備考）。ダイアログは画面の中央に出す（下から出るシートにしない）。マウスを乗せたときの色を付ける |

- 押せる部品の大きさ（44px 以上）と、入力欄の文字の大きさ（16px 以上）は、どの幅でも守る。
- 履歴の表は、js.html で PC 用の HTML を作るのではなく、同じ HTML を CSS の grid で表の形に並べる。これで幅を変えたときも作り直さずに済む。
- 確かめ方: `ui_checks.js` に、幅 768px と 1280px の確認を足す（横にスクロールが出ない、タブの位置、履歴の列）。画像は3つの幅で撮る。

## 2・3. 履歴のページ分け

今は 50件ずつ読み、「もっと見る」で続きを足していく。これを、ページを切り替える形にする。

- 設定キー: **`HISTORY_PAGE_SIZE`（初期値 20）を新しく足す**。メニュー「初期設定（シートの作成）」を実行すると、足りないキーとして設定シートに自動で追加される。範囲は 5〜100 とし、範囲外や数字でないときは 20 として扱う。
  - 今の `PAGE_SIZE`（50）は、操作ログの「もっと見る」だけに使う。履歴と操作ログを同じキーにすると、開発環境の設定シートの 50 を手で直す必要があり、操作ログまで 20件になるため、分ける。
- サーバー: `listRecords(ctx, filter, page)` は、ページ番号（1から）を受け取る。返す値に `page`、`pageCount` を足す。ページ数を超えた番号を受け取ったら、最後のページを返す（修正や削除で件数が減ったときのため）。
- 画面: 一覧の下に、次のようなページ送りを置く。
  - 「‹ 前へ」 「1」 … 「4」 「5」 「6」 … 「8」 「次へ ›」
  - 件数の欄の表示: 「21〜40件目 ／ 全154件」
  - ページ番号は、今のページの前後1つ・最初・最後を出し、間は「…」にする（幅375px で1行に収める）。
  - ページを変えたら、一覧の先頭まで戻す。
  - 絞り込みを変えたら1ページ目に戻る。今のページ番号も、絞り込みと一緒に sessionStorage に残す。
  - 修正・削除・復元のあとは、同じページを読み直す。
- 操作ログ（管理者だけが見る）は「もっと見る」のまま変えない。

- バッジが長くなるので、幅375px でカードの1行目が折り返さないか、画像で確かめる。

## 5. 設定者の表示

「h」を「h(氏名)」にする（氏名は入力者マスタの氏名。カッコは依頼の例に合わせて半角）。

- 対象: ホームの現在の設定と最近の記録、履歴の一覧、記録の詳細、修正画面、入力画面の設定者の欄、絞り込みと修正のプルダウン。
- 今はプルダウンなどで全角の「（氏名）」も使っている。これも半角に統一する。js.html に表示用の関数を1つ作り、すべてそこを通す。
- 入力者マスタに無い記入称の記録（移行データで見つからなかった人など）や、氏名が空の人は、記入称だけを出す。
- 画面上部の名前のチップは幅が狭いため、記入称だけのままにする。→ **2026/11/15 の追加依頼で「記入称(氏名)」に変えた**。スマホでは名前を優先して全部見せ（アプリ名の方を縮める）、管理者モードのボタンは「n分」だけにして、はみ出さないようにした。
- スプレッドシートの「設定者」の列は、記入称のままにする（記録した時点の文字を残す方針のため）。

### 6.3 パターン3の置き換え（2026/11/15 の追加依頼）
パターン3は2L麦茶の設定なので、次の記録はパターン3なら 2L(麦茶あり) にする。
- 備考に「2L」だけが書かれている（規則4に当てはまる）

結果: 10件を置き換えた（「2L」だけ3件、空7件）。2L(麦茶なし) は 6件から3件、2L(麦茶あり) は 19件から29件、空は 24件から17件になった。

### 6.2 すでに入っている記録の扱い
- 記録の「生産品種」の列には、品種の名前そのものが入っている。
- 新しいマスタに無い名前（例:「2L麦茶」）が入った記録は、今の入力チェックでは修正できない。品種の欄を変えずに、ほかの欄だけ直す場合も「品種を選び直してください」になる。
- **本番:** まだ取り込んでいないので、新しい規則で変換した CSV を取り込めば、古い名前は入らない。
- **開発環境（案）:** 変換のためのコードは作らない。docs/05 §3 の手順どおりにスプレッドシートを作り直し、新しい CSV で取り込み直す。本番の手順の練習にもなる。
  - 開発環境で登録したテストの記録は消える。残したい場合は、記録の品種を一括で置き換える管理者メニューを作る（コードが増える）。
- 基準パターンマスタの「主要品種」を手で直すのは、**取り込みのあと**にする。取込はパターンマスタを CSV の内容で置き換えるため、先に直すと消える。この順番を docs/05 §3.3 に書き足す。
