# 02 システム構成

- 版: v1.0（2026/11/14。初版）
- 元資料: 要件定義 2章・11章、構築手順 1・2・5・8章
- 役割: 全体の構成、フォルダとファイル、反映手順、環境を決める

---

## 1. 全体構成

```
[スマホ / PC のブラウザ]
   │  index.html（css.html と js.html を include で埋め込む）
   │  google.script.run（非同期）
   ▼
[GAS ウェブアプリ（Code.gs）]  … 実行ユーザー: 自分 / アクセス: 全員
   │  SpreadsheetApp・CacheService・LockService・DriveApp・Utilities
   ▼
[スプレッドシート（このスクリプトの紐づけ先）]
   ├─ 圧力設定変更履歴   … 記録の本体
   ├─ 基準パターンマスタ
   ├─ 入力者マスタ
   ├─ 品種マスタ
   ├─ 設定
   └─ 操作ログ
[Google ドライブ]
   ├─ 移行用フォルダ（MIGRATION_FOLDER_ID）… 移行 CSV を置く
   └─ バックアップ用フォルダ（BACKUP_FOLDER_ID）
```

- 外部の API やライブラリは使わない。
- 画面から呼ぶ関数は 06 で決めたものだけにする。

### 2.1 Code.gs のセクション構成

各セクションの先頭に、次の見出しコメントを置く。

```
// =====================================================
// 【Records】 記録の登録・修正・削除
// =====================================================
```

| 順 | セクション | 内容 |
|---|---|---|
| 1 | 【Api】 | `doGet`、`include`、`handle_`、`AppError`、画面から呼ぶ公開関数（06 §2〜§5） |
| 2 | 【Config】 | 定数（シート名、列の対応 `COLUMNS`、燃料 `FUELS`、データ区分）、`getSettings_` |
| 3 | 【Utils】 | 日時の整形（Asia/Tokyo）、"HH:mm" の正規化、数値の丸め、ハッシュ、uuid |
| 4 | 【Repository】 | `withLock_`、`readAll_`、`findRowIndex_`、`appendRow_`、`updateRow_`、見出し名からの列の特定 |
| 5 | 【Masters】 | パターン・入力者・品種の取得、`findPattern_`、`findOperator_` |
| 6 | 【Auth】 | 管理者パスワード（スクリプトプロパティ）の照合、トークンの発行と確認、失敗回数のロック |
| 7 | 【Validator】 | 入力チェック（04 §4） |
| 8 | 【Records】 | 登録、修正、削除、元に戻す、採番、マスタとの差異の判定 |
| 9 | 【Query】 | 今の設定、直近の記録、履歴の検索と並べ替え、ページ分け |
| 10 | 【Log】 | 操作ログの追記と取得 |
| 11 | 【Migration】 | 移行 CSV の取込と照合 |
| 12 | 【Backup】 | バックアップの作成と古いものの整理、トリガーの登録 |
| 13 | 【Menu】 | `onOpen` のカスタムメニューと、その実行関数 |

- 内部用の関数は、名前の末尾に `_` を付ける（画面からは呼べないようにする）。
- `Tests.gs` は Code.gs の関数を呼ぶだけにする。Code.gs からは Tests.gs を呼ばない。

## 3. appsscript.json

```json
{
  "timeZone": "Asia/Tokyo",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "ANYONE_ANONYMOUS"
  }
}
```

- 組織内に限るときは、`access` を `DOMAIN` にする（D-24）。
- `oauthScopes` は書かない（GAS が自動で判定する）。

### 3.1 貼り替えでの反映手順

| GAS エディタのファイル | 作り方 | 貼る原本 | 本番 | 開発 |
|---|---|---|---|---|
| Code.gs | 最初からある | `gas_app/Code.gs` | ○ | ○ |
| Tests.gs | ＋ → スクリプト | `gas_app/Tests.gs` | × | ○ |
| index | ＋ → HTML | `gas_app/index.html` | ○ | ○ |
| css | ＋ → HTML | `gas_app/css.html` | ○ | ○ |
| js | ＋ → HTML | `gas_app/js.html` | ○ | ○ |
| appsscript.json | プロジェクトの設定 →「マニフェスト ファイルをエディタで表示する」 | `gas_app/appsscript.json` | ○ | ○ |

1. 原本の中身を丸ごとコピーし、GAS エディタのファイルの中身と置き換えて保存する。
2. ウェブアプリに反映するときは、「デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン → デプロイ」を選ぶ（URL は変わらない）。
3. 確認だけなら「テスト デプロイ」の URL（/dev）を使う。

## 4. データとドライブ

- データはすべて、スクリプトが紐づいたスプレッドシートに置く（`SpreadsheetApp.getActiveSpreadsheet()`）。シートの定義は 03。
- フォルダの ID は設定シートに置く（`MIGRATION_FOLDER_ID`、`BACKUP_FOLDER_ID`）。
- 移行 CSV は、移行用フォルダに決まった名前（03 §4）で置く。

---

## 5. 通信

- 画面からは `google.script.run.withSuccessHandler().withFailureHandler().関数名(...)` で呼ぶ。js.html の `api(関数名, ...引数)` で包み、Promise を返す（06 §10）。
- サーバーの公開関数は、すべて `{ok, data, error}` の形で返す（06 §1.2）。Date 型は返さず、文字列にする。
- 通信中はローディングを表示し、同じボタンは押せなくする。

---

## 6. 認証とセッション

- Google のログインは使わない。`Session.getActiveUser()` も使わない（匿名でアクセスするため、利用者を判別できない）。
- 画面から呼ぶ関数は、第1引数に `ctx = { operatorId, token }` を受け取る。
  - `operatorId`: 画面で選んでいる入力者ID（K-03）。localStorage に保存する（K-19）。
  - `token`: 管理者モードのトークン。なければ `null`。sessionStorage に保存する。
- 管理者のトークンは `CacheService.getScriptCache()` に30分保存する（04 §3）。
- サーバーは毎回、`operatorId` が入力者マスタの有効な人かを確かめる。

---

## 7. デプロイ

1. 開発環境: テスト デプロイ（/dev）で確認したあと、「新しいデプロイ → ウェブアプリ」で作る。
2. 本番環境: 本番用のスプレッドシートから別のプロジェクトを作り、同じ手順で作る（Tests.gs は貼らない）。
3. 2回目からは、同じデプロイを編集して版を上げる（URL を変えない）。
4. デプロイ ID とスクリプト ID は、計画書・docs・history に書かない。
5. 本番環境へのデプロイは、ユーザーの指示があるまで行わない。

## 9. local_preview.html の生成

- `node tools/build_local_preview.js` で、`gas_app/` から1つの HTML を作る（作り方は 05 §9）。
- GAS に貼らなくても、ブラウザで画面と動きを確かめられる。データは `tools/gas_fakes.js` の代用品で動く。
- 画面を変えたら、必ず作り直す。

---

## 10. 性能

- 記録は年に約90件、10年でも1,000件程度なので、毎回シート全体を読む（`getDataRange().getValues()`）。キャッシュは使わない。
- ホームの表示は、1回の呼び出し（`getInitialData`）で必要なデータをまとめて返す。
- 履歴は、サーバー側で絞り込み・並べ替え・ページ分けをして、50件ずつ返す。
