## 1. 概要

### 1.1 目的
ボイラの圧力設定を変えたときに、その内容をスマホからすぐ記録できるようにする。
これまで Excel にためてきた履歴はスプレッドシートへ移し、今後の閲覧はスプレッドシートとアプリの両方から行えるようにする。

### 1.2 現状と課題
| 項目 | 現状 | 課題 |
|---|---|---|
| 記録 | Excel（`ボイラ圧力設定変更履歴.xlsx`）に手入力 | PC の前でないと入力できない。現場で変えた直後に記録しにくい |
| 圧力の値 | 毎回手入力 | 基準パターンと値が合わない記録がある（4件） |
| 設定者 | 頭文字を手入力 | 表記がそろっていない（`y` と `ｙ`）。マスタに無い記入者（`ヒ`）がいる |
| 変更理由 | 備考に自由記述 | 生産品種の書き方がばらばらで、品種ごとに集計・検索しにくい |
| 時刻 | 文字列と時刻の値が混在 | 並べ替えや絞り込みが正しく動かない |
| 閲覧 | Excel ファイルを開いて見る | 今の設定がどれか、すぐに分からない |

### 1.3 今回の範囲
| 区分 | 内容 |
|---|---|
| 対象 | 圧力設定の変更をスマホから入力する |
| 対象 | 既存の履歴154件をスプレッドシートへ移す |
| 対象 | アプリで今の設定、履歴、基準パターン表を見る |
| 対象 | 登録した記録を修正・削除する（権限あり） |
| 対象外 | 通知（メール・チャット）。将来対応 |
| 対象外 | 集計画面とグラフ（Excel の「集計サマリー」にあたるもの）。必要ならスプレッドシート側で作る |
| 対象外 | ボイラ本体や計器とのデータ連携 |

## 2. システム構成

| 項目 | 内容 |
|---|---|
| 作り方 | Google Apps Script（GAS）の HtmlService による1ページのアプリ（タブで切り替え） |
| データ | スプレッドシートに紐づいたスクリプトで持つ |
| 環境 | 開発用（`ボイラ圧力設定DB_開発`）と本番用（`ボイラ圧力設定DB`）のスプレッドシートを分ける |
| 公開設定 | 「次のユーザーとして実行: 自分」「アクセスできるユーザー: 全員」。社内の規定で使えなければ組織内に切り替える |
| 使う端末 | スマホが基本。PC からも使える |
| 設定値 | スプレッドシートの「設定」シートにキーと値で持つ |
| 秘密情報 | 管理者の暗証番号はハッシュ化して保存する。デプロイ ID やスクリプト ID は計画書に書かない |

```
[スマホ / PC のブラウザ]
        │ HTTPS（GAS ウェブアプリの URL）
        ▼
[GAS（HtmlService + サーバー関数）]
        │ SpreadsheetApp
        ▼
[スプレッドシート]
  ├─ 圧力設定変更履歴
  ├─ 基準パターンマスタ
  ├─ 入力者マスタ
  ├─ 品種マスタ
  ├─ 設定
  └─ 操作ログ
```

## 3. 利用者と権限

### 3.1 利用者
| 区分 | 想定する人 | できること |
|---|---|---|
| 設定者 | ボイラの圧力設定を変える担当者（今は7名＋過去の記入者） | 記録の登録、閲覧、自分の記録の修正 |
| 管理者 | 設備担当の責任者など | 上記に加えて、全件の修正・削除、操作ログの確認 |

### 3.2 本人の確認
- Google アカウントでのログインはしない。
- 設定者は、入力者マスタから**プルダウンで選ぶ（自己申告）**。
- 前回選んだ設定者はブラウザに保存しておき、次に開いたとき最初から選ばれているようにする。
- 「本人の記録」は、記録の設定者と、今選んでいる設定者が同じかどうかで判断する。

### 3.3 管理者モード
- 画面から暗証番号を入れて管理者モードに入る。
- 暗証番号はハッシュ化して「設定」シート（またはスクリプトプロパティ）に保存する。
- 入れたあと30分有効のトークンをサーバー側（ScriptCache）に持ち、その間は管理者の操作ができる。

## 4. 入力項目の定義

現行の Excel の列を引き継ぎ、「生産品種」を新しく足す。

| # | 項目 | 必須 | 入力方法 | 初期値 | チェック |
|---|---|---|---|---|---|
| 1 | 日付 | ○ | 日付を選ぶ | 今日 | 未来の日付は注意を表示 |
| 2 | 時刻 | ○ | 時刻を選ぶ（時:分） | 今の時刻 | — |
| 3 | 設定パターン | ○ | 基準パターンマスタから選ぶ（有効なものだけ） | 直前の記録のパターン | — |
| 4 | メインボイラ | ○ | 「ガス」「重油」のどちらかを選ぶ | 直前の記録の燃料 | — |
| 5 | 設定圧力(MPa) | ○ | **パターンを選ぶと自動で入る。手で直せる** | パターンのメイン圧力 | 0.50〜0.80 の範囲で小数2桁。マスタと違う値のときは注意を表示（登録はできる） |
| 6 | 設定者 | ○ | 入力者マスタから選ぶ（有効な人だけ） | 前回選んだ人 | — |
| 7 | 生産品種 | 任意 | 品種マスタから選ぶ | 空 | — |
| 8 | 備考 | 任意 | 自由記述（200文字まで） | 空 | — |

補足:
- 設定圧力は、マスタを参照するのではなく**値そのものを記録に保存する**。後でマスタの値を改定しても、過去の記録が変わらないようにするため。
- サブボイラの圧力と号機（No.5 / No.8 など）は、現行どおり記録しない。必要なときは備考に書く。
- 圧力の範囲（0.50〜0.80）は仮の値。「設定」シートで変えられるようにする。

### 4.1 システムが自動で持つ項目
| 項目 | 内容 |
|---|---|
| 記録ID | 一意の ID（例: `R-20261114-0001`）。移行データにも振る |
| 変更日時 | 日付と時刻をまとめた日時（並べ替えと絞り込みに使う） |
| マスタとの差異 | 設定圧力がパターンのメイン圧力と違えば TRUE |
| 登録日時 / 登録者 | 登録した日時と、そのとき選ばれていた設定者 |
| 更新日時 / 更新者 | 最後に修正した日時と人 |
| 版数 | 楽観ロック用。修正のたびに1つ増やす |
| 削除フラグ | 論理削除用 |
| データ区分 | `移行`（Excel から移したもの）か `アプリ`（アプリで登録したもの） |

## 5. 記録の状態と、修正・削除の権限

記録の状態は「有効」「削除済み（論理削除）」の2つだけにする。承認の流れは設けない。

| 操作 | 設定者（本人） | 設定者（他人） | 管理者 |
|---|---|---|---|
| 登録 | ○ | — | ○ |
| 閲覧 | ○ | ○ | ○ |
| 修正 | 自分の記録（**期限なし**） | × | 全件 |
| 削除 | × | × | 全件（論理削除） |
| 削除の取り消し | × | × | ○ |

- 修正と削除は、すべて操作ログに残す（誰が、いつ、どの記録の、どの項目を、何から何に変えたか）。
- 移行データ（データ区分＝`移行`）を直せるのは管理者だけ。

## 6. 画面の要件

### 6.1 共通
- スマホを優先する。幅375pxで崩れないことを確認する。
- タップできる大きさは44px以上。
- 見た目は既存アプリ（`02.ロッカーキー貸出管理(Gemini)` の `css.html`）の色づかい（主色 Sky #0284c7 など）に合わせる。
- 画面の下にタブを置く。タブは「ホーム」「入力」「履歴」「パターン表」の4つ。
- ブラウザ標準の alert / confirm は使わず、アプリ独自の確認ダイアログにする。
- 通信中はローディングを表示し、ボタンの二度押しを防ぐ。

### 6.2 画面一覧
| # | 画面 | 主な内容 |
|---|---|---|
| S-01 | ホーム | **今の設定**（最新の記録の パターン・メインボイラ・設定圧力・変更日時・設定者・品種）を大きく表示。「設定を変更して記録する」ボタン。直近5件の記録 |
| S-02 | 入力 | 4章の項目。パターンを選ぶと圧力が自動で入る。マスタと違う値なら注意を表示。登録前に確認ダイアログ、登録後に完了表示 |
| S-03 | 履歴一覧 | 新しい順に表示（スマホではカード形式）。絞り込み: 期間、パターン、燃料、設定者、品種。マスタと違う値の記録には印を付ける。少しずつ読み込む（例: 50件ずつ） |
| S-04 | 記録の詳細と修正 | 1件の全項目を表示。権限があれば修正できる。管理者なら削除・削除の取り消しもできる |
| S-05 | 基準パターン表 | パターンごとのメイン圧力、サブ圧力、主要品種、注記の早見表 |
| S-06 | 管理者モード | 暗証番号の入力。入ったあとは削除済みの記録の表示と、操作ログの閲覧ができる |

## 7. スプレッドシートの構成（概要）

詳しい列の定義は、後で `plan/03_データ設計.md` にまとめる。

| シート | 内容 | 主な列 |
|---|---|---|
| 圧力設定変更履歴 | 記録の本体 | 記録ID、日付、時刻、変更日時、設定パターン、メインボイラ、設定圧力(MPa)、設定者、生産品種、備考、マスタとの差異、データ区分、登録日時、登録者、更新日時、更新者、版数、削除フラグ |
| 基準パターンマスタ | パターンごとの基準の圧力 | パターン、メイン圧力、サブ圧力、主要品種、注記、有効フラグ、改定日 |
| 入力者マスタ | 設定者 | 記入称、氏名、表示順、有効フラグ |
| 品種マスタ | 生産品種の選択肢 | 品種名、表示順、有効フラグ |
| 設定 | アプリの設定値 | キー、値、説明（例: 圧力の範囲、管理者暗証番号のハッシュ） |
| 操作ログ | 登録・修正・削除の記録 | 日時、操作、記録ID、操作者、変更内容 |

- 閲覧はスプレッドシートでもできるようにする。そのため「圧力設定変更履歴」は、人が見やすい列を左に並べ、システム用の列は右に寄せる（必要なら列をグループ化して隠す）。
- 人がスプレッドシートで記録を直接書き換えるのは避ける運用にする（保護や警告の設定を検討する）。

## 8. マスタの定義

### 8.1 基準パターンマスタ（Excel から引き継ぐ初期値）
| パターン | メイン(MPa) | サブ(MPa) | 主要品種 | 注記 |
|---|---|---|---|---|
| 1 | 0.66 | 0.64 | 小型 | 2024.7.19時点 |
| 2 | 0.67 | 0.65 | 1.5L、2L水&SP、2L(麦茶以外) | 2024.11.22時点更新 |
| 3 | 0.68 | 0.66 | 2L(麦茶)、CUP有 | 2024.11.22時点更新 |
| 4 | 0.69 | 0.67 | （なし） | |
| 5 | 0.65 | 0.63 | 小型 | 2025.1.29新設（メイン0.70→0.65に変更） |

- Excel の「主要品種」欄は「メイン圧力: 0.66（小型）」のように圧力の値も含んだ文字列なので、移すときに品種だけを取り出す。
- サブ圧力は今のところ常に「メイン − 0.02」だが、計算では出さずマスタに値を持つ。

### 8.2 入力者マスタ
- Excel の入力者マスタ（7名: h / ｙ / Y / L / ノ / キ / I）を引き継ぐ。
- 履歴にだけ出てくる「ヒ」は退職済みの記入称なので、**無効の人として登録**する（プルダウンには出さず、過去の記録の表示にだけ使う）。
- 氏名の読みの誤り（「…ノブユキユキ」）は、移すときに直す。

### 8.3 品種マスタ（初期値の案）
履歴の備考から抜き出した品種をもとに、次の案で作る。この案で決定（12章 U-02）。

| 品種名（案） | 備考での書き方の例 |
|---|---|
| 小型 | 小型、小型の為(1L)、小型(水) |
| 0.35L | 0.35k |
| 0.5L | 0.5k、0.5m、0.5L |
| 0.525L(スポーツ) | 0.525生産(スポーツ) |
| 0.55L(水) | 0.55m(水)、0.55m水生産、550ml |
| 1.5L | 1.5L、1.5L生産 |
| 2L(水) | 2L(水)、2L(水)生産の為 |
| 2L麦茶 | 2L麦茶、２L麦茶 |
| 2L(その他) | 2L、2L POS生産 |
| CUP有 | — |
| その他 | 上のどれにも当てはまらないもの |

### 8.4 マスタの更新方法
- マスタはスプレッドシートで直接編集する（アプリにマスタ管理画面は作らない）。
- 消さずに「有効フラグ」を外して使わなくする。過去の記録の表示が崩れないようにするため。

## 9. 既存データの移行方針

移行元: `reference/ボイラ圧力設定変更履歴.xlsx` の「圧力設定変更履歴」シート（154件、2025/01/21〜2026/11/12）

| # | 問題 | 対応方針 |
|---|---|---|
| 1 | 時刻が文字列（137件）と時刻の値（17件）で混在。「08:31」のような0埋めもある | すべて時刻の値（h:mm）にそろえる |
| 2 | 12行目の時刻が数値の 0、132行目が文字列の「0:00」 | 0:00 として移す（U-04） |
| 3 | 日付と時刻が別の列 | 両方の列を残したうえで、まとめた「変更日時」の列を足す |
| 4 | 136行目（08/16）と137行目（08/12）で日付の順番が逆転 | 変更日時の順に並べ替えて移す |
| 5 | パターンと圧力がマスタと合わない（88、131、141、145行目） | **値は変えずにそのまま移し**、「マスタとの差異」を TRUE にする |
| 6 | 設定者の「y」（ASCII、8件） | マスタの「ｙ」（全角）にそろえる。大文字の「Y」とは別の人として扱う |
| 7 | 設定者の「ヒ」（14件、退職済み）がマスタに無い | **そのまま移し**、入力者マスタに無効の人として登録する |
| 8 | 設定者が空欄（12、14、88行目） | 空欄のまま移す（アプリでの新規登録では必須） |
| 9 | 文字列に読み仮名が付いている（18個。例: 「2L麦茶」に「ムギチャ」） | 読み仮名を取り除き、本文だけを移す |
| 10 | 備考の品種の書き方がばらばら。全角の「２L麦茶」もある | 置き換え表で生産品種の列に振り分ける（案）。**元の文字列は備考にそのまま残す**（U-03） |
| 11 | 備考が空欄（6件） | 空欄のまま移す |
| 12 | 集計サマリーのシートとグラフ（Excel の数式） | 移さない |
| 13 | 壊れた名前定義（`#REF!`）、H列の書式だけのセル | 移さない |

- 移したあと、件数（154件）と、パターン別・燃料別の件数が Excel と合っていることを確認する。
  - パターン別: P1 8件、P2 64件、P3 30件、P5 52件
  - 燃料別: ガス 126件、重油 28件
- 移行に使う変換表（設定者・品種の置き換え）は、作業のあとも記録として残す。
