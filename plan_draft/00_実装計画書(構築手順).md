## 3. スプレッドシートの作成

1. Google ドライブに `ボイラ圧力設定DB_開発` を作る（本番用の `ボイラ圧力設定DB` は、テストが終わってから同じ手順で作る）。
2. 次のシートを作り、1行目に見出しを入れる（列の詳細は `plan/03_データ設計.md` で決める）。

| シート | 用途 |
|---|---|
| 圧力設定変更履歴 | 記録の本体 |
| 基準パターンマスタ | パターンごとの基準の圧力 |
| 入力者マスタ | 設定者 |
| 品種マスタ | 生産品種の選択肢 |
| 設定 | アプリの設定値（キーと値） |
| 操作ログ | 登録・修正・削除の記録 |

3. 見出しの行を固定し、見やすい書式にする（日付は yyyy/mm/dd、時刻は h:mm、圧力は 0.00）。
4. 「設定」シートに最初の値を入れる。
   - 圧力の範囲（0.50〜0.80）
   - 履歴を1回に読み込む件数（50件）
   - 管理者暗証番号のハッシュ（アプリの初期設定用の関数で書き込む）
5. 記録とマスタのシートには「編集時に警告を表示」の保護をかけ、うっかり直接書き換えるのを防ぐ。

## 4. 既存データの移行

### 4.1 マスタの取込
1. 基準パターンマスタ: Excel の5件を取り込む。「主要品種」の欄から、品種名だけを取り出す。
2. 入力者マスタ: Excel の7名を取り込む。氏名の読みの誤りを直し、退職済みの「ヒ」を無効の人として足す。
3. 品種マスタ: 要件定義 8.3 の一覧を入れる。

### 4.2 履歴のクレンジング
`tools/` に変換スクリプトを用意し、次の順で変換する（変換の内容は要件定義 9章）。

| 順 | 処理 |
|---|---|
| 1 | Excel の「圧力設定変更履歴」シートを読む（A〜G列、2〜155行目） |
| 2 | 読み仮名を取り除く |
| 3 | 時刻を h:mm の時刻にそろえる（文字列・数値・0埋めのどれでも） |
| 4 | 日付と時刻から「変更日時」を作る |
| 5 | 設定者の「y」を「ｙ」にそろえる |
| 6 | 備考から生産品種を振り分ける（置き換え表を使う。元の備考は残す） |
| 7 | パターンのメイン圧力と比べて「マスタとの差異」を付ける |
| 8 | 変更日時の順に並べ、記録ID を振る。データ区分は `移行` にする |
| 9 | 取込用のファイル（CSV など）と、変換結果のレポートを出す |

### 4.3 取込と照合
1. 開発用のスプレッドシートに取り込む。
2. 次の点が合っていることを確認する。
   - 件数が154件
   - パターン別の件数（P1 8件、P2 64件、P3 30件、P5 52件）
   - 燃料別の件数（ガス 126件、重油 28件）
   - マスタとの差異が4件（元の Excel の88、131、141、145行目）
   - 期間が 2025/01/21〜2026/11/12
3. 品種の振り分け結果の一覧を利用部署に見てもらう。
4. 本番の取込は本番公開の直前に行う。それまでに Excel 側で増えた記録も含めて、もう一度変換する。

## 5. GAS プロジェクトの作成

1. 開発用のスプレッドシートから「拡張機能 → Apps Script」でプロジェクトを作る（スプレッドシートに紐づける）。
2. プロジェクト名を `ボイラ圧力設定管理_開発` にする。
3. `gas_app/` のファイルを GAS エディタに作る（Code.gs、index.html、css.html、js.html。appsscript.json はプロジェクトの設定で「マニフェストを表示」にして貼る）。
4. タイムゾーンを `Asia/Tokyo` にする。
5. 初期設定用の関数を一度実行し、権限を承認する（管理者暗証番号のハッシュの書き込みなど）。

## 6. 段階的な実装

| Phase | 内容 | 終わったと言える状態 |
|---|---|---|
| 1 | データ層とマスタ: シートの読み書き、マスタの取得、設定値の取得、操作ログ | Node のテストと GAS 上でマスタと履歴が読める |
| 2 | 入力画面: パターンを選ぶと圧力が自動で入る、マスタと違う値の注意、確認ダイアログ、登録、二重送信の防止 | スマホから登録でき、シートに1行増える |
| 3 | ホームと履歴: 今の設定の表示、直近5件、履歴の一覧・絞り込み・少しずつの読み込み、基準パターン表 | 移行した154件が正しく表示・絞り込みできる |
| 4 | 修正・削除と管理者: 本人による自分の記録の修正、管理者モード（暗証番号とトークン）、論理削除と取り消し、楽観ロック | 権限どおりに修正・削除でき、操作ログに残る |

## 7. テスト

| 種類 | 方法 | 主な確認内容 |
|---|---|---|
| ロジックのテスト | `tools/` の Node スクリプトで、GAS に依存しない処理をテストする | 時刻の変換、マスタとの差異の判定、修正できるかの判定、品種の振り分け |
| ローカルでの画面確認 | ローカルのプレビュー用 HTML を作り、幅375pxで確認する | レイアウト、タップできる大きさ、ダイアログ |
| GAS 上の結合テスト | 開発環境に `Tests.gs` を貼って実行する | シートの読み書き、ロック、ログ |
| スマホの実機テスト | iPhone と Android で開発用 URL を開く | 入力から登録まで、履歴の絞り込み、管理者モード |
| 同時に使ったとき | 2台から同時に登録・修正する | 書き込みが壊れない。楽観ロックで知らせが出る |
| 移行の照合 | 4.3 のとおり | 件数と内訳が Excel と合う |

## 8. デプロイ

1. GAS エディタで「デプロイ → 新しいデプロイ → ウェブアプリ」を選ぶ。
   - 次のユーザーとして実行: 自分
   - アクセスできるユーザー: 全員（使えなければ組織内）
2. 出てきた URL を利用者に配る。スマホのホーム画面に追加する手順も案内する。
3. 2回目からは `gas_app/` の原本を GAS エディタに貼り替え、「デプロイを管理 → 編集 → 新しいバージョン」で**同じデプロイの版を上げる**（URL は変わらない）。
4. 実装する AI は、作業のたびに「貼り替えが必要なファイル」を報告する。
5. デプロイ ID とスクリプト ID は計画書や docs に書かない。
6. 本番用は、本番のスプレッドシートに紐づく別のプロジェクトとして作る。`Tests.gs` は貼らない。
